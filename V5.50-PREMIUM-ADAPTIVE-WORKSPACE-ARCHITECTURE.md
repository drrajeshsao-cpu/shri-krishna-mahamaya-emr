# Mahamaya Clinic EMR V5.50 — Premium Adaptive Clinical Workspace

**Build:** 2026.08.15-R27  
**Release type:** UI/UX, responsiveness, navigation and non-auth performance hardening  
**Clinical data scope:** V5.41C clinical/therapeutic datasets preserved; no new autonomous diagnostic or prescribing behavior added.

## Design goal
V5.50 converts the already feature-rich EMR into a calmer, faster, device-adaptive clinical workspace for **mobile, tablet, laptop and desktop**. The design target is high-reliability, mission-control-like clarity: obvious hierarchy, one visible next action, rapid keyboard/touch navigation, restrained visual noise and traceable build identity. References to organizations such as ISRO, NASA, AIIMS, AIIA or NIA describe the desired quality bar only; this build is not endorsed, certified or affiliated with those institutions.

## What changed
- Premium deep-teal / clinical-green visual system with restrained warm-gold accents.
- System-font stack only; no new web-font/network dependency.
- Adaptive breakpoints for small phones, large phones, tablets, laptops and wide desktops.
- Safe-area support for notches/home indicators and landscape mobile use.
- Mobile bottom navigation retained and polished; desktop command bar retained.
- Existing Fast Flow retained as the sequential encounter navigator.
- New **Ctrl/Cmd + K Quick Command** palette opens existing modules without changing their logic.
- Improved touch targets, input focus states, form density, dashboard hierarchy, cards, tables, drawers and sticky actions.
- Device-aware spacing and density; wide screens show more information without forcing excessive scrolling.
- Lazy/async decoding applied to non-brand images by the isolated premium shell.
- Reduced-motion and higher-contrast accessibility support.
- New premium assets are cached by the existing PWA service worker.

## Login / Firebase safety boundary
Authentication and cloud behavior were deliberately excluded from the refactor. The following V5.41C functions were byte-for-byte compared and preserved:
- `unlockApp()`
- `lockApp()`
- `restoreSession()`
- `savePins()`
- `SKMC_ROLE_BRIDGE`

No PIN values, Firebase configuration, login selectors, role semantics, logout behavior, cloud persistence, credential handling or record authorization logic were modified by V5.50.

## Responsive device matrix
- **≤360 px:** narrow-phone compact layout.
- **361–430 px:** standard mobile two-column clinical shortcuts with one-column hero fallbacks.
- **431–767 px:** large-phone layout.
- **768–1023 px:** tablet workspace with 2–4 column clinical grids where appropriate.
- **1024–1399 px:** laptop / standard desktop layout.
- **≥1400 px:** wide desktop clinical command-center layout.
- Low-height landscape mode receives a shorter header/dock and denser Fast Flow panel.

## Performance philosophy
The release avoids redesigning the clinical engines or auth layer. Speed work is limited to low-risk presentation optimizations: no external font requests, lightweight CSS overrides, one isolated vanilla-JS navigation shell, lazy image decoding and PWA caching of the new static assets. The large clinical datasets remain separate JSON assets and are not duplicated into the new shell.

## Workflow sequence retained
1. Patient & Visit
2. Complaints & HPI
3. History & Vitals
4. Prakriti & Lifestyle
5. Clinical Examination
6. Assessment & Diagnosis
7. Investigations / SLAIE
8. Ayurveda Assessment
9. Plan / Prescription / Safety / PDF

The existing 12-step Fast Flow remains available for finer navigation.

## Validation boundary
Static syntax, structural, auth-preservation, asset-reference and ZIP-integrity checks can be completed in the build environment. Local Chromium navigation is administrator-blocked in this environment, so final real-device regression must still be performed after GitHub Pages deployment on an Android phone/PWA, tablet, laptop and desktop browser, including login, save/reopen, Firebase cross-device sync and PWA cache refresh.
